# 知识大厦全景网页

**本 skill 做一件事：把一份知识清单生成一个单文件全景网页。** 清单是人写的 md 原稿（或 JSON），网页是一个 HTML 文件，数据、样式、画布绘制、交互全在里面，双击就能打开，也可以单独发给别人。没有框架、没有依赖，装了 Node.js 就能用，不用 `npm install`。

```
学科目录/<名称>-节点清单.md（人写、人审）──tools/build.mjs 检查并生成──▶ 学科目录/outputs/<名称>.html
```

- 更新知识只改 md，再生成一次；改页面功能才改本 skill 的 `template.html`，改完各学科重新生成。
- md 写法见下面“md 原稿格式”；JSON 字段见第二节。md 里每个字段都对应一个 JSON 字段，转换规则在 `lib/md.js`。
- 其他资料（drawio、PDF、表格）可以先改写成 md；不方便时也可以按第二、三节直接写 JSON，`build.mjs` 两种都收。

```
.claude/skills/knowledge-map-web/
  SKILL.md                      本文件：md 格式、页面位置、JSON 字段、资料元素怎么对应
  template.html                 网页模板：样式、画布绘制、交互；生成时把数据和检查代码嵌进去
  lib/md.js                     md 原稿 → 数据
  lib/formula.js                Markdown `$...$` / `$$...$$` LaTeX → KaTeX 富文本；旧记法的降级显示
  lib/normalize.js              数据检查与整理：编号、引用、依赖方向、无环、分组同层；推出连线和区域颜色（生成时和网页里都用它）
  vendor/katex/                 内嵌 KaTeX、样式和字体；保证生成的单文件网页离线渲染教材级公式
  tools/build.mjs               生成单文件网页
  tools/serve.mjs               边改边看：盯着 md，保存就重新生成，浏览器自动刷新
  tools/build-lib.mjs           上面两个共用的部分
  tools/normalize.test.mjs      回归用例
  schema/knowledge.schema.json  JSON 的正式定义：只允许列出的字段，每个字段注明显示在页面哪里
  examples/sample.md            md 原稿示例：用到了 md 的全部写法
  examples/sample.json          JSON 示例：5 个知识，用到了全部字段
  package.json                  只声明 lib/*.js 是 ES 模块，没有依赖
```

## 命令（在仓库根目录，只要装了 Node.js）

```bash
K=.claude/skills/knowledge-map-web/tools
node $K/build.mjs 数学/数学大厦/数学大厦-节点清单.md 数学/数学大厦/outputs/数学大厦.html   # 检查并生成；有错误就列出来，不写文件
node $K/build.mjs 清单.md 输出.html --json 输出.json                            # 另外写出 JSON
node $K/build.mjs 清单.md --check                                               # 只检查
node $K/serve.mjs 数学/数学大厦/数学大厦-节点清单.md 数学/数学大厦/outputs/数学大厦.html   # 边改边看：打开 http://127.0.0.1:8080/
node --test $K/*.test.mjs                                                       # 回归用例
```

生成的网页放在学科项目的 `outputs/` 目录下。一个网页就是一张图。

## md 原稿格式

完整示例见 `examples/sample.md`；数学大厦的 `数学/数学大厦/数学大厦-节点清单.md` 是一份大的真实例子。

```
# 标题（只是给人看的）
## 页面设置                      - 标题：… / - 编号写法：正则 / - 学段：小学、初中… / - 推荐：编号、编号 / - 保存键：…
                                 下面一张表：| 区域 | 颜色 | 位置 | 说明 |   位置是 0～1，楼层里靠左还是靠右
## 主干链                        1. **名称**　下面每行缩进写一条路径：名称 编号 → 名称 编号 …；⇢ 表示“往上通向”；
                                 “a → b → c / d” 表示从 b 再分出一条 b → d
## 第 N 层　楼层名：一句说明      楼层，N 从 0 起，越往下越基础
### 编号 名称　〔学段〕            分组：一类知识。没有知识点时它本身就是一张卡片
#### 编号 名称                    分组里的知识点：一张卡片，名字前显示分组的短名
## 思想方法                      两种写法（可混用）：
                                 旧格式：- **名称**：说明｜出现在：编号、编号
                                 新格式（富方法卡）：### 方法名，下面用"- 字段：内容"写说明、方向、依据、信号、出现在、标签、例子、易错
## 题型入口（不推荐）            模板保留此能力，当前设计不建议使用
                                 ### 题型名
                                 - 分类名：编号（提示）
```

其余二级标题（如“怎么读”“节点总数”）只给人看，不进页面。字段写成 `- 字段：内容`：

| md 字段 | 写在 | JSON 字段 | 说明 |
|---|---|---|---|
| 标题行的编号、名称、〔学段〕 | 分组、知识点 | `id`、`full`、`stage` | 知识点的学段跟分组；知识点名称同时是卡片名 |
| 短名 | 分组 | `name` | 卡片上的名字，不写就用标题里的名称 |
| 区域 | 分组 | `region` | 页面设置区域表里的一个；知识点跟分组 |
| 标志 | 分组、知识点 | `one` | 卡片第二行：标志公式或定理 |
| 是什么 / 后来发展到 / 用在哪 / 例子 / 往上通向 | 都可以 | `what` / `next` / `use` / `eg` / `upto` | |
| 从哪来 | 都可以 | `from` | 显示时“⇐推出 3.1”会写成“由 函数（3.1）” |
| 依赖 | 没拆的分组 | `deps` | 多行格式：`- 依赖：` 后换行，每条来源用 `  - 来源：编号` 开头，下面缩进写 `种类：`、`方法：`、`条件：`、`步骤：`（编号列表）。详见第七章示例 |
| 要点 / 注释 / 条件 / 反例 / 标签 | 都可以 | `points` / `notes` / `conditions` / `counterexamples` / `tags` | 一行用“；”隔开，或在下面缩进写“  - 一条” |
| 类型 / 重要度 | 都可以 | `type` / `importance` | 起点、结论、中间步；0～3 |

- **公式记法**：按 Markdown 常用方式直接写 LaTeX。行内公式写 `$a^{m/n}=\sqrt[n]{a^m}$`。块公式可以和字段写在同一行：`- 标志：$$\int_a^b f(x)\,\mathrm dx$$`；也可以写成多行，解析器会原样读取到独立的结束 `$$`，缺少结束符时给出警告：

  ```md
  - 标志：$$
  \int_a^b f(x)\,\mathrm dx
  $$
  ```

  模板统一用内嵌 KaTeX 渲染，Canvas 卡片、悬停、主干字幕、分组列表、搜索结果和说明栏显示同一份富文本公式；KaTeX、CSS 和字体全部嵌入最终 HTML，双击离线可用。未加 `$` 的旧内容仍能显示，但只作兼容，不保证教材级公式排版。
- **依赖的种类**：多行格式中 `种类：` 字段写 `推出`、`用到`、`推广`、`特例`、`前提`，不写默认为 `用到`。知识点没有单独的”依赖”字段时，从”从哪来”里读。
- **拆过的分组**（下面有 `####` 知识点）在图上是一个框，框上的名字、点开后的整体讲解来自分组的字段；它没有依赖，别处引用时写到具体的知识点编号。
- **md 不支持**：连线的 `detail`（长说明）和 `main`（主干线加粗）。需要时直接写 JSON。

`tools/build.mjs --check` 检查结构以外的规则：编号唯一、引用存在、依赖不往高层指、无环、枚举值合法、分组的知识点在同一层。页面加载时做同样的检查，有错误就在页面上列出来，不画图；提醒（编号不符合 idPattern、主干某一步没有依赖、连线的方法不在方法表里）在命令行和浏览器控制台里，要逐条看。字段拼写和多余字段用 `schema/knowledge.schema.json` 对照检查。

## 一、页面上每个位置显示什么

```
┌ 顶栏 ─────────────────────────────────────────────────────────────────┐
│ ①title      说明文字（固定）            [找一个知识… /] [现在可以学] ⑫进度 │
├ 第二行 ───────────────────────────────────────────────────────────────┤
│ 主干：[▶ ②chains]  方法：[⑨methods]  ③图例                              │
├───────────────────────────────────────────────────────┬───────────────┤
│ ④楼层名 │ ⑤卡片  ■/●/○ 名称 ◆                          │ ⑧说明栏         │
│  F7 …   │     ╲ ⑥线：来源 → 本知识（主干线更粗）          │（点开知识后出现）│
│  F0 …   │                    ⑦悬停提示                  │               │
│         │                    ⑩底部卡片：主干字幕 / 方法说明 │               │
└───────────────────────────────────────────────────────┴───────────────┘
```

| 位置 | 显示内容 | 来自字段 |
|---|---|---|
| ① 顶栏标题 | 页面名称 | `title` |
| ② 主干按钮 | 主干名；点了逐步播放 | `chains[].name`、`path` |
| ③ 图例 | 区域名和颜色；数据里有类型或条件时，加“■ 起点 ● 结论 ○ 中间一步 ◆ 有条件” | `regions[]`；`nodes[].type`、`conditions` |
| ④ 左侧楼层名 | `F{L}` 加楼层名，从下往上 | `layers[].L`、`name` |
| ⑤ 卡片 | 两行：第一行圆点＋（分组名 › ）短名（圆点颜色＝区域，形状＝类型：■ 起点、● 结论、○ 中间一步；有条件时右端琥珀色 ◆；学过的圆点变 ✓）；第二行是标志公式或定理 | `region`、`type`、`group`、`name`、`conditions`、`one` |
| ⑤ 分组框 | 同一分组的卡片排在一起，外面画浅色框，框上写分组名；点框名看分组的整体讲解和整个分组的家谱（框里所有知识点的来源和后续） | `groups[]`、`nodes[].group` |
| ⑤ 卡片位置 | 上下由楼层定；同层左右由区域 `anchor` 和推导关系自动摆 | `layer`、`regions[].anchor` |
| ⑥ 线 | 来源 → 本知识；悬停、点开时着色、光点流动；主干线在全景里更粗更深 | `deps[].id`、`deps[].main` |
| ⑦ 悬停提示 | ★ 名称、一句话、成立条件、类型·标签·区域·学段、来源和后续个数；点开某知识后再加它和中心知识的关系（怎么推的） | `importance`、`name`、`one`、`conditions`、`type`、`tags`、`region`、`stage`、`deps[].how` |
| ⑧ 眉题、标题、标签 | 编号 · 楼层 · 学段；★ 完整名称；区域、类型、标签、来源和后续个数 | `id`、`layer`、`stage`、`importance`、`full`、`region`、`type`、`tags` |
| ⑧ 成立条件 | 逐条 ◆ | `conditions` |
| ⑧ 它是什么 | 正文，下面列要点（公式、条文） | `what`、`points` |
| ⑧ 从地基走到这里 | 沿依赖走到最低层的最短路 | 自动算（需要有 L=0 的知识） |
| ⑧ 从哪来 | 正文；直接来源列表：名称、关系类型、怎么推的、【方法】、〔条件〕，下一行是详细说明 | `from`；`deps[]` 的 `id`、`kind`、`how`、`method`、`condition`、`detail` |
| ⑧ 后来发展到 | 正文；直接后续列表（同上，取后续知识里指向它的那条依赖） | `next`；自动算 |
| ⑧ 再往上 | 将来怎样严格化、推广（不画线） | `upto` |
| ⑧ 用在哪、例子 | 正文 | `use`、`eg` |
| ⑧ 反例与易错 | 逐条 ✗ | `counterexamples` |
| ⑧ 注释 | 逐条，灰色 | `notes` |
| ⑥ 连线 hover | 方法的详细说明（方向、依据、信号、易错）；通过标签模糊匹配方法名 | `methods[]` 全部字段 |
| ⑨ 方法按钮 | （模板保留此能力）悬停高亮用到它的知识 | `methods[].name`、`nodes` |
| ⑭ 题型入口按钮 | （不推荐使用）模板保留此能力，但当前设计不建议写题型入口——题型分类容易过时且分散注意力 | `entries[].pattern`、`targets[].case`、`nodes`、`hint` |
| ⑩ 主干字幕 | “A → B” 加这一步怎么推的 | 相邻两步依赖的 `how`，没有时用 B 的 `one` |
| 搜索 | 按编号、名称、一句话、标签、正文、要点、条件搜；框为空时列推荐 | `featured` 或自动取撑起知识最多的 8 个 |
| ⑫ 进度 | 已学个数；悬停按学段统计 | `stages`、`nodes[].stage` |

**正文里引用别的知识**：写成全角括号加编号，如“用到了极限思想（6.1）”“（3.1、6.1）”，页面会变成可点链接；编号须符合 `idPattern`。

**正文富文本**：普通文字按纯文本处理；公式使用 Markdown 常见的 `$...$` 或 `$$...$$` LaTeX 定界符，由内嵌 KaTeX 渲染。不要直接写 HTML；资料里的 `<b>` 等标签要改成普通文字或对应字段。

## 二、JSON 字段

完整定义见 `schema/knowledge.schema.json`；`examples/sample.json` 用到了每一个字段。

### 顶层

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `title` | 是 | 字符串 | 页面名称 |
| `layers` | 是 | 数组 | 楼层 |
| `regions` | 是 | 数组 | 区域 |
| `nodes` | 是 | 数组 | 知识 |
| `chains` | 否 | 数组 | 主干：`{"name", "path": [编号…]}`，从底层往上；多条支路写 `"paths": [[…],[…]]`，播放走第一条 |
| `methods` | 否 | 数组 | 思想方法，见下"methods 字段" |
| `entries` | 否 | 数组 | 题型入口（不推荐使用）：看到什么题型→用哪个工具，见下"entries 字段" |
| `groups` | 否 | 数组 | 分组：同一类的几个知识点，见下 |
| `featured` | 否 | 编号数组 | 搜索框为空时推荐 |
| `idPattern` | 否 | 正则 | 编号写法，默认 `\d+\.\d{1,2}`；S01、R30 这类写 `[A-Z]\d{2}` |
| `stages` | 否 | 字符串数组 | 进度统计的学段，默认 小学、初中、高中、大学 |
| `storageKey` | 否 | 字符串 | 保存“已学”的键名；同一份数据换版本时保持不变 |

### `layers[]` 楼层　`regions[]` 区域

| 字段 | 必填 | 说明 |
|---|---|---|
| `layers[].L` | 是 | 整数，0 最底下 |
| `layers[].name` | 是 | 楼层名，≤ 8 字 |
| `layers[].sub` | 否 | 一句说明（暂不显示） |
| `regions[].name` | 是 | 区域名 |
| `regions[].color` | 否 | `#RRGGBB`，不写按色板取 |
| `regions[].anchor` | 否 | 0～1，楼层里大致靠左还是靠右；横跨各区的写 0.5 |
| `regions[].desc` | 否 | 一句说明（暂不显示） |

### `groups[]` 分组

一类知识拆成几个知识点时用分组把它们归在一起，例如“导数的应用”分组里有导数与单调性、极值、最值、优化问题。知识点用 `group` 指向分组。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 分组编号，不能和知识重名；符合 `idPattern` 时正文里的“（编号）”能链接到分组 |
| `name` | 是 | 分组名：框上的标题、卡片前缀、搜索结果 |
| `full` / `stage` / `one` | 否 | 说明栏标题、学段、悬停在框名上时的一句话 |
| `what` / `from` / `next` / `use` / `eg` / `upto` / `points` / `notes` | 否 | 分组的整体讲解，和知识的同名字段写法一样 |

同一分组的知识必须在同一层（`tools/build.mjs --check` 会检查）。只有一个知识点的类不必建分组，它本身就是一张卡片。

### `methods[]` 思想方法

贯穿多个知识的方法、工具或思想。工具栏第二行"方法"按钮，悬停高亮用到它的知识，点击固定并展开方法卡。

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 方法名：工具栏按钮、方法卡标题 |
| `desc` | 否 | 一句话说明 |
| `nodes` | 是 | 用到这个方法的知识编号 |
| `labels` | 否 | 线上标签：属于这类方法的具体做法名（字符串数组），如 `["作差", "作商"]` |
| `direction` | 否 | 方向：这类方法往哪走、用来做什么 |
| `basis` | 否 | 依据：凭什么能这么做（正文里可用编号引用节点） |
| `signal` | 否 | 信号：什么问题特征时想到用这个方法 |
| `examples` | 否 | 范例数组：具体怎么用（每条可引用节点） |
| `pitfalls` | 否 | 易错数组：常见陷阱 |

md 的 `## 思想方法` 里两种写法可以混用：

**旧格式**（一行搞定）：`- **变化率**：一个量变得多快｜出现在：1.1.1、1.1.2`

**新格式**（富方法卡）：
```
### 比较
- 说明：通过作差或作商比较大小
- 方向：确定大小关系
- 依据：实数的序性质（S01）
- 信号：看到"证明 A > B""比较大小"
- 出现在：3.1、3.2
- 标签：作差；作商
- 例子：
  - 用作差法证明 AM-GM（3.1）
- 易错：
  - 作差后忘记判断符号
```

### `entries[]` 题型入口（不推荐使用）

"看到什么题型→用哪个工具、走哪个方向"的反向索引。模板保留此能力，数据里有 `entries` 时工具栏按钮才出现。当前设计不建议使用——题型分类容易过时且分散注意力。

| 字段 | 必填 | 说明 |
|---|---|---|
| `pattern` | 是 | 题型名：看到的问题特征 |
| `targets[]` | 是 | 各分类 |
| `targets[].case` | 是 | 分类名 |
| `targets[].nodes` | 是 | 对应的知识编号 |
| `targets[].hint` | 否 | 简短提示 |
| `tags` | 否 | 搜索分组标签 |

md 格式（`## 题型入口`）：
```
## 题型入口

### 解不等式
- 一次：R10（移项）
- 二次：R43（判别式分类）
- 含参：R50、R51（分类讨论）
```

### `nodes[]` 知识

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一编号 |
| `name` | 是 | 卡片短名，≤ 8 字 |
| `layer` | 是 | 楼层 `L` |
| `region` | 是 | 区域 `name` |
| `what` | 是 | 它是什么，一两句大白话 |
| `one` | 建议 | 卡片第二行：这个知识的**标志公式或定理**，看一眼就知道它是什么，≤ 24 字，如 `f′>0 ⇒ 递增；f′变号 ⇒ 极值`；没有公式的写一句定义，如“若p则q；充分、必要；任意、存在”。不要写成“各类函数怎么求导”这种只说主题的话 |
| `full` | 否 | 完整名称 |
| `stage` | 否 | 学段 |
| `type` | 否 | `起点`（直接承认或定义）/ `结论`（推出的结果）/ `中间步`（为推出结论而经过的一步） |
| `importance` | 否 | 0～3，显示为 ★ |
| `tags` | 否 | 标签数组，如 `["【定理】"]` |
| `conditions` | 否 | 成立条件数组，如 `["Δ≥0"]` |
| `points` | 否 | 要点数组：公式、结论条文，每条一行 |
| `from` / `next` / `use` / `eg` | 否 | 从哪来 / 后来发展到 / 用在哪 / 例子 |
| `upto` | 否 | 再往上（不算依赖） |
| `counterexamples` | 否 | 反例、易错数组 |
| `notes` | 否 | 注释数组：同源、互逆、对照、与别的资料的接口 |
| `group` | 否 | 所属分组的 `id` |
| `deps` | 否 | 直接依赖，见下 |

### `nodes[].deps[]` 连线（写在被推出的知识上）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 来源编号，须在同层或更低层；可简写成字符串 |
| `kind` | 否 | `推出`（由来源的结论推出）/ `前提`（来源是它成立的前提）/ `用到`（默认）/ `推广` / `特例` / `对照` |
| `how` | 建议 | 推导步骤。多行格式中写在 `步骤：` 下的编号列表里，解析时自动用分号连接。主题大厦中必须详细写清每步操作 |
| `method` | 否 | 这一步用的方法名。多行格式中写 `方法：展开法`；连线标签从此字段读取 |
| `condition` | 否 | 这一步要加的条件 |
| `detail` | 否 | 补充说明（显示在节点 tooltip 的推导步骤下方） |
| `main` | 否 | `true` 表示主干线 |

**硬规则**：来源不能高于本知识，不能成环。资料里出现“高层推出低层”时，要么楼层分错了，要么那条应写进 `upto`。

## 三、资料里的元素怎么对应

| 资料里的东西 | 写进哪里 |
|---|---|
| 一个概念、定理、公式、方法条目（drawio 里带文字的方框，Markdown 的标题或条目，表格的一行） | 一个 `node` |
| 方框标题 / 完整名称 / 一句话概括 | `name` / `full` / `one` |
| 方框里的正文、公式行 | `what`（概括）＋ `points`（逐行） |
| 【公理】【定义】【定理】等前缀 | `tags`，从 `name` 里去掉 |
| 起点、无条件结论、中间一步（常用颜色区分） | `type` |
| 有条件才成立（常标成橙色、带“条件标签”） | `conditions`；条件只针对某一步推导时写在那条连线的 `condition` |
| ★ 重要程度 | `importance` |
| ✗ 反例、易错 | `counterexamples` |
| 注释、同源、互逆、“同见某某〔编号〕” | `notes` |
| 箭头、“由……推出”“用到……” | 结论的 `deps`；方向一律“来源 → 结论” |
| 推导线与前提线（实线 / 虚线） | `kind`：`推出` / `前提` |
| 箭头上的短标签 | `how`；多行的长说明放 `detail` |
| 线上的【方法】、手法 | `method`，并在 `methods` 里登记 |
| 加粗的主干线 | `main: true` |
| 贯穿多处的思想方法、手法 | `methods`（`nodes` 列出用到它的知识）；有方向/信号/依据/范例/易错时用富方法格式。方法详细说明在连线 hover 中显示 |
| 外借的公式、定理 | 直接作为起点节点放入图中（`## 第 0 层`），有自己的公式和描述，通过节点搜索找到 |
| "看到什么题型→用哪个工具"的索引（不推荐） | `entries`（`targets` 列出各分类和对应知识） |
| 分区、分支、章节标题框（区域背景、彩色标题条） | `regions` |
| 一类知识下面的几个具体知识点（如一节课里的几个小节） | 知识点各是一个 `node`，这一类建一个 `groups` 分组，知识点写 `group` |
| 层级、地基 → 屋顶、章节先后 | `layers`；没有层级就按依赖深度算：无来源放 L=0，其余放“来源中最高层 + 1” |
| 主线、学习路线 | `chains` |
| 图例、标题、页面说明、装饰框 | 不转换 |
| 只在文字里写的跨区关系（如“S01→R01”） | 还原成对应知识的 `deps`，不要因为图上没画箭头就漏掉 |

转换原则：
- **只转资料里有的内容**，改写成大白话可以，不编造知识；资料没写的字段留空。
- **编号**：资料自带就保留，并设置 `idPattern`；没有就按“楼层.序号”编。
- **一一对应可追查**：转换完列一张清单给用户：资料里有多少知识、连线、方法，JSON 里各有多少；哪些被合并、拆分、丢弃或改成 `upto`，各写一句理由。
- 运行 `tools/build.mjs --check` 修到零错误，并对照 schema 检查字段。

## 五、页面自带的交互

- 全景：整栋楼一屏放下，自动挑选让文字最大的楼宽；开场各层从地面依次升起。
- 全景只有一种：全部知识点卡片，同一分组的卡片排在一起、外面套一个浅色框（只是分组的样式，不是另一层视图）。滚轮、＋−、双击平滑缩放，不会重新排版。点框上的分组名，看这一组的整体讲解和家谱。
- 悬停节点：300ms 延迟后弹出 tooltip，显示标题、公式、条件、描述和推导过程（步骤）。同一节点上移动不重新触发。
- 悬停连线或连线上的方法文字：300ms 延迟后弹出 tooltip，显示该方法的详细说明（方向/依据/信号/易错）。
- 点开：只留家谱，按楼层摆，空楼层收窄；只画”最近的一步”；悬停家谱里的知识，描出它与中心之间的所有路。推导线上显示方法标签（`【方法名】`），缩放足够大时可见，用背景色断开线条。
- 第二行只显示主干播放按钮：点了逐步播放推导链。
- 操作：拖空白处移动；滚轮、右下角 ＋−、双击缩放；拖卡片会弹回并拽动相连知识；`/` 或 ⌘K 搜索（支持拼音首字母和跳字模糊匹配，如输入”ndl”能搜到”牛顿第二定律”）；选中后 ↓ 往来源、↑ 往后续、←→ 同层换；`Esc` 回全景；`+ - 0` 缩放和复位。
- URL 直达：选中知识后地址栏变成 `#编号`，如 `#3.1`；可以当书签保存、从笔记里直接跳进去；浏览器前进后退也能在家谱之间切换。
- 学习进度存在浏览器里；”现在可以学”标出前置都学过的知识。支持”减少动态效果”。

## 七、内容编写指引——节点放什么、连线放什么

本节是内容层面的设计规则。格式已在前几节定义，这里说的是**写什么内容、放在哪里、怎么写才能让学生看图就学会推导**。

两类内容的分工：
- **主题大厦**（如不等式大厦、二次函数大厦）：展开逐步推导，推导过程详写每一步的方法操作和公式结果
- **学科全景**（如数学大厦）：只写来源关系和标志公式，不展开推导细节

本节的推导过程写法主要面向主题大厦；学科全景遵循项目 CLAUDE.md 的共同基础和本 skill 的格式规范，只写来源关系和标志公式。

### 核心原则

知识大厦的价值不在于罗列知识点，而在于让学生**沿拓扑结构追踪推导链**，在反复阅读中建立框架思维、方法运用能力和工具记忆。一切内容围绕这个目标组织：

- **节点 = 结论**：这个知识点是什么、条件、公式描述、怎么从更基础的结论一步步推出来的
- **连线 = 方法**：推导中用了什么方法（怎么做的），hover 连线看方法的详细教学说明
- 学生 hover 节点看推导过程，对其中某个方法有疑问时 hover 连线看方法说明；工具/公式的描述在拥有它的源节点的 `what` 字段

### 节点 tooltip 显示什么

| 内容 | 写在哪个字段 | 要求 |
|------|------------|------|
| 标题 | `name` / `full` | 知识点的名称，不含编号 |
| 公式 | `one`（标志） | 核心公式/定理，LaTeX 格式，突出显示 |
| 条件 | `conditions` | 成立的前提条件（如 $a,b > 0$） |
| 描述 | `what`（是什么） | **这个公式/定理的详细说明**：是什么、怎么用、什么场景适用、等号条件、几何意义等。这是公式的核心描述，学生看节点就能理解这个公式的含义和用法。推导步骤中引用其他节点的公式时（如「平方非负」），被引用节点上的 `what` 就是那个公式的说明 |
| **推导过程** | `deps[].how` | **最重要的部分**，见下面的详细要求 |

节点 tooltip **不放**：方法的通用说明（方向/依据/信号/易错）——这些放在连线 hover 上。推导步骤中实际引用的公式、条件和代入过程**必须保留**，不能省略。工具/公式的详细说明（是什么、怎么用）放在**被引用的源节点自身的 `what` 字段**，不在当前节点重复列出。

### 推导过程怎么写（deps 的 how 字段）

每个 dep 的 `how` 是用分号 `；` 分隔的步骤序列，页面渲染为编号步骤。每一步必须写清楚：

1. **条件/前提**：`▼ 条件：$a > 0$，$b > 0$`
2. **方法 + 具体操作**：不是只写方法名，要写出这个方法**做了什么**。如 `【作差法】$\dfrac{1}{a} - \dfrac{1}{b} = \dfrac{b-a}{ab}$`
3. **工具 + 实际公式**：用了什么公式/定理，把公式写出来。如 `由「平方差公式」$b^{2}-a^{2} = (b+a)(b-a)$`
4. **操作后的结果**：每步操作后变成了什么。如 `因此 $a^{2}+b^{2} \ge 2ab$`

**示例**（R55 重要不等式）：
```
由「平方非负」$(a-b)^{2} \ge 0$；【展开法】用「完全平方公式」展开：$a^{2} - 2ab + b^{2} \ge 0$；【移项法】两边 $+2ab$，得 $a^{2}+b^{2} \ge 2ab$；等号 $\iff a=b$
```

**反面**（不要这样写）：
- ❌ `【配凑法】配凑后得证` — 没说怎么配凑的
- ❌ `见 R28` — 不要引用 ID，直接写出内容
- ❌ `（见标志）` — 不要占位符

### 连线上显示什么

连线上的文字（画布上可见）：`【方法名】`，只显示方法，不显示工具名。

连线 hover tooltip **只显示方法的详细说明**：

| 内容 | 来源 | 说明 |
|------|------|------|
| **方法说明** | `methods[]` 的 `desc` | 这个方法是什么、典型用法 |
| **方向** | `methods[]` 的 `direction` | 这个方法往哪个方向走 |
| **依据** | `methods[]` 的 `basis` | 凭什么能这么做 |
| **信号** | `methods[]` 的 `signal` | 什么时候想到用这个方法 |
| **易错** | `methods[]` 的 `pitfalls` | 常见陷阱 |

连线上**不显示工具/公式的描述**——工具/公式的说明在源节点自身的 `what` 字段。连线 A→B 已经告诉你用了 A 的公式推出 B，点击 A 即可看到 A 的公式描述。

### 思想方法（methods）怎么写

每个方法用 `### 方法名` 开头，包含以下字段：

```md
### 配凑
- 说明：凑成”平方 + 常数”，或凑出和、积为定值
- 方向：凑成已知不等式的形式，或凑出能用均值不等式的结构
- 依据：平方非负；均值不等式求最值要定值
- 信号：二次式定号、求最值；对称多项式不等式；条件最值
- 出现在：R28、R55、R17、R66
- 标签：配凑；配方；分组；补项；待定系数；乘 1 法；轮换求和
- 易错：
  - 凑完要核对等号能否取到
```

`标签` 字段很重要：连线 hover 时，`setEdgeTip` 用依赖末尾的 `d.method`（即连线上显示的方法名）去匹配 METHODS，先按名称精确匹配，再按标签模糊匹配（如"展开法"去掉"法"后匹配到标签"展开"→找到"恒等变形"方法）。**当前限制**：一条依赖只有一个 `d.method`，如果推导步骤中用了多个方法（如先【代换法】再【展开法】），连线上只显示末尾标注的那一个方法的说明。要看其他方法的说明，需要找到那个方法作为主方法的其他连线。

### 外借公式的处理

不再单独写 `## 工具箱`。外借的公式/定理直接作为**起点节点**放在 `## 第 0 层`，和其他公理、定义一起管理。例如，平方差公式作为节点：

```md
### T01 平方差公式
- 标志：$a^{2}-b^{2} = (a+b)(a-b)$
- 区域：基础
- 类型：起点
- 标签：【恒等式】
- 条件：无额外限制
- 是什么：用在作差比大小时分解定号；根式裂项时分母有理化
```

推导过程中用 `「平方差公式」` 引用这个节点的公式，步骤正文必须写出实际公式。

### 固化的展示结构

以下结构适用于所有**主题大厦**（不等式大厦、二次函数大厦、恒等式大厦等），生成时统一遵守，不得改变。学科全景（如数学大厦）只写来源关系和标志公式，推导过程可省略，其余结构相同。

**参考实例**（摘自不等式大厦）：

起点节点（无推导过程）：
```md
### S01 实数大小
- 标志：$a\gt b \iff a-b\gt 0$（$a-b$ 是正数）
- 区域：起点
- 类型：起点
- 标签：【公理】
- 条件：任意实数
- 是什么：三歧性；传递性：$a \gt b$，$b \gt c \Rightarrow a \gt c$
```

单来源节点（推导过程详细）：
```md
### R55 重要不等式
- 标志：$a^{2}+b^{2} \ge 2ab$
- 区域：实数域
- 类型：结论
- 重要度：1
- 条件：任意实数
- 是什么：任意两个实数的平方和不小于它们积的两倍；是均值不等式的基础；等号 $\iff a=b$
- 依赖：
  - 来源：R46
    种类：推出
    方法：展开法
    步骤：
      1. 由「平方非负」$(a-b)^{2} \ge 0$
      2. 【展开法】用「完全平方公式」展开：$a^{2} - 2ab + b^{2} \ge 0$
      3. 【移项法】两边 $+2ab$，得 $a^{2}+b^{2} \ge 2ab$
      4. 等号 $\iff a=b$
```

多来源节点（多块推导过程）：
```md
### P42 四种平均数不等式链
- 标志：$a,b\gt 0$
- 区域：正数域
- 类型：结论
- 重要度：3
- 标签：【高考常用】
- 条件：a,b>0
- 是什么：调和 $\le$ 几何 $\le$ 算术 $\le$ 平方平均；四种平均数的完整排序；等号均 $\iff a=b$
- 依赖：
  - 来源：P37
    种类：推出
    步骤：
      1. ▼ 条件：$a, b \gt 0$
      2. 由「几何平均 ≥ 调和平均」$\sqrt{ab} \ge \dfrac{2ab}{a+b}$，即 $G \ge H$
  - 来源：P29
    种类：推出
    步骤：
      1. 由「基本不等式」$\dfrac{a+b}{2} \ge \sqrt{ab}$，即 $A \ge G$
  - 来源：R71
    种类：推出
    步骤：
      1. 由「平方平均 ≥ 算术平均」$\sqrt{\dfrac{a^{2}+b^{2}}{2}} \ge \dfrac{a+b}{2}$，即 $Q \ge A$
      2. 合起来：$H \le G \le A \le Q$，等号均 $\iff a = b$
```

思想方法（连线 hover 显示）：
```md
### 恒等变形
- 说明：作差后分解、分母有理化、穿根前分解
- 方向：把式子换成相等、更好用的样子（用 = 连接）
- 依据：运算律和起点节点中的恒等式
- 信号：要定正负就分解成因式之积；要比较就展开合并；根式和就有理化
- 标签：展开；提公因式；因式分解；通分；合并整理；分母有理化
- 易错：
  - 与等价变形分清：恒等变形变式子（=），等价变形变不等式（⟺）
```

**节点 tooltip（hover 节点时弹出）：**
1. 标题（节点名称）
2. 公式（`one` 字段，hero-formula 大字渲染）
3. 条件（`conditions` 字段，金色显示——**必须写**：公式成立的前提条件，如 $a,b > 0$、$x \in \mathbb{R}$、$n$ 为正整数等。填写实际的研究对象、适用范围和必要前提；无额外限制时写"无额外限制"。md 格式：`- 条件：x>0` 或多条件用分号 `- 条件：a,b>0；a≠b`）
4. 公式描述（`what` 字段——**必须详细**：这个公式/定理是什么、怎么用、什么场景适用、等号条件、几何意义等。一般 2-5 句话，写清含义和使用场景。起点节点写清公理/定义的内容和意义）
5. 推导过程（`deps[].how` 字段——**必须详细**：每步写清条件→方法+操作→工具+公式→结果）
   - **有几条连线进来，就有几块推导过程**。每块以"源节点 ──→ 当前节点"的流程头开始，下面是该条连线对应的编号步骤，块之间用分隔线隔开
   - 例如：P42（四种平均数不等式链）有 3 条连线进来（P37、P29、R71），tooltip 里就有 3 块推导，分别说明 $H \le G$、$G \le A$、$A \le Q$ 怎么来的
   - **起点节点**（公理、定义、研究对象）没有推导过程，tooltip 只显示前 4 项（标题、公式、条件、描述）
   - **推导只有一步时**，写清那一步即可，不必凑步骤数
   - **方法字段**：多行格式中写 `方法：展开法`，连线标签从此字段读取并显示在画布上，hover 连线时显示该方法的详细说明

以上 5 项为**必填项**（起点节点除外第 5 项）。模板还支持以下**可选字段**，有数据时自动显示在推导过程之后，不需要时留空：`points`（要点）、`counterexamples`（易错）、`notes`（注释）。

**连线标签（画布上可见）：**
- 只显示 `【方法名】`，不显示工具名
- 方法名用青色

**连线 tooltip（hover 连线时弹出）：**
- 源节点 ──→ 目标节点（流程头）
- 方法的通用说明：方向、依据、信号、易错
- **不显示工具/公式的描述**

**职责分工（不可混淆）：**
- 节点负责：公式 + 公式描述 + 推导过程（含具体操作步骤）
- 连线负责：方法名 + 方法的通用教学说明（什么时候用、怎么判断、注意什么）
- 工具/公式的"是什么、怎么用"：放在拥有这个公式的节点的 `what` 字段
- 方法的"是什么、怎么用"：放在连线 hover 的方法说明

### 精简原则

- **节点公式描述详细**：`what` 字段必须详细写清这个公式/定理是什么、怎么用、什么场景适用；这是学生了解公式含义的唯一入口
- **推导过程详细**：`how` 字段必须详细，每步写清方法操作和结果
- **方法说明详细**：`methods` 的描述字段（方向/依据/信号/易错）要完整，这是学生学习方法的入口；只在连线 hover 显示
- **工具/公式不放连线**：连线上只有方法名；工具的描述在源节点的 `what` 字段
- **不要 ID 引用**：所有面向学生的文本中不出现 P25、R55 等编号，直接写出内容
- **不推荐写题型入口**：题型分类容易过时且分散注意力；模板保留 entries 的解析和渲染能力（通用性），但当前设计不建议使用

### 交互设计规则

| 交互 | 延迟 | 说明 |
|------|------|------|
| hover 弹出 tooltip | 300ms | 防止快速滑动时遮挡视线 |
| 离开后 tooltip 消失 | 100ms | 快速消失但留余量让鼠标移到 tooltip 上 |
| 同一节点/连线上移动 | 不重新触发 | 避免闪烁 |
| 连线文字区域 | 也可触发 | 不用精确对准线条 |

### 布局规则

- 节点按楼层分行，同层内用**重心法**（barycenter）自动排列——每个节点的横坐标趋向其相邻节点的平均位置，减少连线交叉
- 只有 1-2 个邻居的节点吸引力更强（0.25），确保单链节点紧跟其父/子节点
- 连线标签（只有方法名）在线上显示，用背景色断开线条；位置通过碰撞检测避开节点和其他标签
- 节点卡片高度根据公式实际渲染高度自适应，四周留 padding
